## Two workflows

`tests.yml` runs the suite across Python 3.11, 3.12 and 3.13, installing the
checkout rather than a published wheel so the gate always tests the code in the
PR. There is no compile step and no vendor adapter yet, so nothing in the suite
touches a network or a GPU and the whole thing runs on a plain runner.

`prose.yml` runs the prose gate over changed markdown and the PR body, scoped by
`.prose-mint.toml`.

## The one decision worth recording

**klin does not ship prose-mint, so the prose action is a cross-repo reference**
to `ostin-pil/claude-plugins/prose-mint@main`. The alternative was installing
`prose-mint` from PyPI and running a `bulk` walk, which avoids the coupling but
loses what the action is actually for: scanning only what the PR changed, plus
the PR body, which is a different medium with different wrapping rules.

The coupling is real and worth naming. A change to that action lands in klin's
CI without a klin commit, and pinning to `@main` is what makes that possible.
Pin a SHA instead if this ever stops being two repos with one author.

The local gate stays on PyPI (`uvx --from prose-mint prose-mint bulk --strict .`
in the lifecycle manifest), which mirrors how the sibling repo splits local from
CI.
