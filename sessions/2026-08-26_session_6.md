# Session 6 — What is on this machine, and what made it

**Date:** 2026-08-26
**Branch:** `feature/session-6-index` (worktree `.claude/worktrees/session-6-index`)

`fetch` answered where a model came from. Nothing answered the other half, so
Barinn had 1,384 generated images on disk and no way to ask which of them a
non-commercial model had produced. This session builds the index, and then
spends most of its length on the things the index made visible.

## The index

The load-bearing fact is that a generated image is self-describing. ComfyUI
writes its whole API-format graph into a PNG `tEXt` chunk, so the base model,
the LoRA stack with strengths, the seed, the sampler settings and both prompts
are in the file. Of 1,384 images, 1,315 carry one. The provenance was never
lost, only unindexed, which makes this a scan rather than an archaeology
project.

Chunk framing is a length, a four-byte type, a payload and a CRC, so `png.py`
reads it with the standard library and klin still ships two dependencies. A
scanner walking a hundred thousand files also has no business decoding pixels,
which is what opening an image would do.

`comfy.py` walks the graph backwards from the sampler along its `model` input
rather than collecting nodes whose class name contains `Lora`. The shortcut is
wrong twice over: it loses the order the stack was applied in, and it counts
loaders sitting in the graph wired to nothing. Both cases are in the corpus.

Three decisions worth keeping.

**The index is derived, the ledger is truth.** The database lives beside the
cache and never in a repository, because the rule that no weights and no raw
generation output enter a game repo covers a table describing them too.

**The licence verdict is computed at query time and never stored**, for the same
reason `ship_ok` is absent from a record. The index describes files that do not
change while the policy around them changes constantly.

**Machine-scoped, project-tagged.** One output directory serves every project on
a machine. Roots say where to look, claim patterns say what belongs to the
calling project, and a file no project claims is indexed and counted rather than
dropped. Barinn claims 221 of 1,394; the rest are Crimeariver's.

## Models resolve by identity, not by name

Each model an image used is traced back to a ledger record through the weights
tree, matched on `(st_dev, st_ino)`. `fetch --as` hardlinks rather than copies,
so the tree's entry and the ledger's path are one file under two names.

The evidence for this being necessary rather than clever: of fourteen recorded
models in Barinn's tree, fourteen resolved by identity and **none** would have
resolved by name. The weights tree is exactly where files get renamed into
something readable, so `Isometrica_Flux` is `isometrica_flux` there and
`dark_fantasy_illustration_Flux-000031` is linked twice under two names, which a
filename match would have called two different models. A name match survives as
a labelled fallback.

An item whose model reaches no record is marked `?` and `ls --check` exits
non-zero on it. A file whose origin is unknown is the case a ship gate exists to
catch, so silence there would invert its meaning.

## Two defects the index exposed in the core

**The ship gate passed over licences klin could not classify.** No family rule a
project writes can match `unknown`: a rule table denies share-alike, or
noncommercial, or whatever it decided about, and nothing in it denies "we could
not tell". So an unclassifiable record passed `audit --ship` in silence, and a
pass meaning "the rules never reached this one" printed identically to one
meaning "the rules applied and were satisfied".

klin now supplies exactly one rule of its own, and it holds no opinion about
licences either: it reports that the audit had a gap. No rule number, since it
was transcribed from nobody's policy document. Ship gate only, since the stage
rule's whole content is that the thing gets written down.

**And fixing that alone would have been worse than the bug.** `families()` tested
an explicit list for truthiness, so `families: []` was indistinguishable from a
missing key and fell through to the identifier, where a `LicenseRef-` id
classified as `unknown`. But an empty list is a *result*: an adapter reading a
vendor's permission flags and finding no restriction writes exactly that. Seven
of Barinn's Civitai LoRAs sat in that state with `allowCommercialUse: [Image,
Sell]` in their sidecars. Closing the gate hole first would have turned seven
quiet misreadings into seven loud false failures.

## Cache drift, which is silent by construction

`cache_dir` resolves from an environment variable so one committed manifest can
describe several machines. The cost is a failure nothing reports: a variable set
when the files were fetched and unset later resolves somewhere else, the records
still point at real files, the audit still passes, and the next fetch downloads
seventeen gigabytes into a second tree. Barinn was in that state for two
sessions.

The check cannot be "do the recorded files exist", which stays true throughout.
It is whether *any* recorded file lives under the cache now in force. A note and
never a failure, because a project may legitimately keep assets outside the
cache and klin cannot tell that apart from a variable that has gone missing.

## Adoption, and then adoption by default

Barinn's tree held sixty-nine gigabytes across five base models, none fetched
through klin, so every image they produced was untraceable. Re-downloading all
of it to learn what was already on the disk is not an answer, and hand-writing
the records means inventing the licences.

Adoption is a fetch minus the transfer. The guards that make a downloaded file
trustworthy are properties of the bytes rather than of how they arrived, so
running them against a local file proves the same thing. A mismatch is refused
outright, because a record is an assertion about provenance and writing one for
a file that failed the vendor's own hash asserts what klin just disproved.

Three of the five adopted with their hashes matching the Hub's. Two refused on
exact byte counts, 7,712 and 40 bytes out, because no published file matches
them; both were locally converted and have no upstream to verify against.

It then became the default rather than a flag, because downloading something the
machine already holds is the common case. Every fetch searches the weights tree
and the cache first, size to shortlist and hash to confirm. A twelve-gigabyte
model already present now records in thirty-three seconds and transfers nothing.
The cache is searched as well as the tree, which matters exactly when
`cache_dir` has drifted.

**Automatic adoption requires a published hash**, and the counter-example is in
this project's own tree: `sd_xl_base_1.0.safetensors` and
`sd_xl_base_1.0_0.9vae.safetensors` are identical in length and are different
models. Adopting on size would have recorded one as the other, silently.
Explicit `--adopt` keeps the looser check because a person named that file.

## Two more, found while adopting

**The Hub's digest was never being checked.** `_declared_sha256` looked for
`lfs.oid`, which is Git LFS's own pointer spelling; the API returns
`lfs.sha256`. klin reported "this vendor publishes no hash" for every repository
on the Hub. This is the same silent-degradation failure `_declared_size` already
warns about for `files_metadata=true`, one function below it.

**Recording the terms was tied to the classification path.** `licence_text` ran
only when classification came back `unknown`, which are unrelated things.
Passing `--families permissive` to settle SDXL's OpenRAIL terms by hand made
klin stop recording the 14,105 characters that justified the decision, and rule
5 then failed a record for a document it had held one run earlier.

## The register, and narrowing a rule to what klin could not read

Two Apache-2.0 models failed Barinn's rule 5 because neither Comfy-Org
repository publishes a `LICENSE` file. The terms were never in doubt; the
document was somewhere else.

`spdx.py` looks an identifier up in the published register. This does not reopen
the no-guessing rule: an SPDX identifier is a key into a register where each
entry has exactly one text, so recording what SPDX says `Apache-2.0` is amounts
to a lookup. An identifier outside the register resolves to nothing, and so does
an unreachable register, because offline should leave the field empty rather
than filled with an invention.

`require` also gained `unless_classified: true`. Rule 5's reasoning is about
terms nobody can look up, and it does not reach `Apache-2.0`. The narrowing
exempts exactly the records klin could read and never the ones it could not, so
an unclassified record still has to carry its terms.

## A correction inside the session

One commit here reverts another. `fix(build)` claimed `packages = ["klin"]` kept
subpackages out of every wheel, which is what setuptools' documentation implies
and is not what this build does. Checked by building both ways and listing the
archives: the two wheels are identical and both carry `klin/fetch/` in full. The
commit fixed nothing and its reasoning was wrong, so it is reverted rather than
left standing as the reason an explicit list is there.

## Where it leaves the consuming project

Barinn's 221 claimed plates go from 68 shippable, 66 failing and 78 untraceable
to **154 shippable, 66 failing and 1 untraceable**. The ledger's ship gate drops
from seven failures to six, and all six are now rule 4 on genuine non-commercial
terms. Nothing fails on a tooling gap.

The one remaining untraceable model is `z_image_base_bf16`, which no published
file matches and which klin therefore refuses to record.
