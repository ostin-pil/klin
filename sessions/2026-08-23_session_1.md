# Session 1 — repo birth and the ledger core

**Date:** 2026-08-23
**Branch:** `main` (repo birth; every session after this one follows the
branch-and-PR lifecycle in the manifest)

## Why this repo exists

A game project needed local ComfyUI, Civitai and HuggingFace integration, and
wanted none of it in the game repo. The extraction was decided in that project's
own decision log, along with the alternatives that were rejected. The short
version: one marketplace monorepo rather than three per-vendor repos, because
the provenance record is shared and would otherwise be invented three times in
three dialects.

The name went from `kiln` to `klin` after a clearance screen. `Kiln-AI/Kiln` is
an active AI-tooling project with an overlapping description, `kiln.fi` is a
large staking platform, and PyPI `kiln` has been taken since 2007. `klin` is
unclaimed on PyPI and npm.

## What was built

The core only, with no vendor adapter, which was the deliberate build order. The
shared core is the reason this is one repo, so it exists before anything depends
on it.

- `klin/ledger.py`, JSONL records, one line per asset, sorted by id on write.
- `klin/policy.py`, licence-family classification and rule evaluation over four
  rule kinds: `require`, `deny`, `prefer`, `assert`.
- `klin/render.py`, the generated block inside a hand-written policy document,
  with a `--check` mode so a hand-edit inside the markers is caught by a gate.
- `klin/manifest.py`, the per-project manifest.
- `klin/cli.py`, `klin ledger list | add | audit | render`.
- The plugin: the `klin-ledger` skill and a `/klin-audit` command.

## Three things settled while building, worth not relitigating

**`ship_ok` is computed at audit time, never stored.** A verdict written into a
record goes stale the moment policy is amended, and a stale pass is worse than
no pass at all. Records persist only `reviewed_at` and an explicit waiver.

**A waiver downgrades a finding rather than removing it.** The first draft
skipped waived records entirely, which meant an accepted risk quietly stopped
appearing in the audit. A waived finding now still prints, tagged, carrying the
same rule text.

**Set-level rules exist because one real rule needs them.** CC BY 4.0 forbids
applying technological measures that restrict the licensed rights, so any CC-BY
asset combined with Steam's DRM wrapper is a breach while either alone is fine.
No per-record field can express that, which is why `build_facts` exists.

## Verified against real data, not only fixtures

The acceptance test ran a real consuming project's manifest and policy document,
not a fixture. Its genuine CC0 asset-pack record passes the ship gate. A
synthetic CC-BY-SA record fails rule 2 and prints that project's own trap text
verbatim. A synthetic research-licensed record fails rule 4 as NonCommercial,
which is the case most likely to be forgotten a year from now and the reason
machine enforcement was chosen over an advisory tool.

## Left open

- **CI is not wired.** The `gh` token lacks the `workflow` scope, so a push that
  adds `.github/workflows/` is rejected. Run `gh auth refresh -s workflow`, then
  add the test and prose workflows mirroring `claude-plugins`.
- No vendor adapter yet. `fetch` and `gen` are named in the CLI's design and in
  the README, and neither is implemented.
- The `fan-art` licence family has no detector and can only be applied by hand
  through `licence.families`. Recorded so the gap is known rather than assumed
  covered.
