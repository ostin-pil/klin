# Session 8: conform, and an installed klin that could not start

**Date**: 2026-08-27
**Branch**: `feature/session-8-conform` (worktree, `.claude/worktrees/session-8-conform`)

## Why now

`conform` has been in the role table since session 1 and in the README's
layout tree since session 2, as the one verb named and not built. The
consuming project had reached it from the other side: its five flat-panel
props cannot be authored until there is a route from a modelling tool to an
asset on its atlas, and its previous session had cleared the last blocker by
hoisting the atlas cell map into a file both sides could read. `produced_by`
being null on all nineteen of its records was the same gap seen from a third
angle.

## What conform actually does

Less than the name suggests, and the narrowness is the point. The consuming
project's atlas is a grid of flat colour swatches, so a material is not an
image to author but a coordinate to point at. Conforming sets every loop of
every face whose slot is named `wood_mid` to the one texel that names the
wood_mid cell, collapses the slots into a single shared material, and
triangulates. Any mesh comes out style-native and nobody painted anything.

Pinning to a coordinate rather than to a colour is what lets one edit of one
image re-grade every asset at once, which is why the export must reference the
shared atlas rather than carry a copy, and why that is now checked.

Blender is a subprocess and never an import, so the half that touches meshes
is `_inside_blender.py`, handed a resolved json job and answering with one
prefixed line. The underscore keeps it out of adapter discovery, where
importing it would fail on `import bpy`.

## The gates, and the one that is a measurement

Blender writes to a temporary file. Every gate runs against that file and it
moves into `staging_dir` only when they all pass, so the manifest's promise
that a validated file is what lands there is structural rather than a matter
of remembering. Asserted per gate.

The uv gate reads the exported file back rather than trusting the scene.
glTF's uv origin is the top left and Blender's is the bottom left, so a pin
that is right in the scene can be inverted in the file and both look equally
clean from inside Blender. Re-importing turns a convention argument into a
number. Compared as sets, because collapsing the slots leaves a re-imported
mesh with nothing to say which face used to be which slot, and because the
set catches more anyway: a uv that never moved, one in the wrong cell, and a
whole layout written upside down.

Geometry checks live in the verb rather than in `policy.py`. Every rule kind
there is a pure function of records, which is why an audit runs on a checkout
holding no assets; a triangle budget would have to open a file or keep a
second copy of a number that already exists in one.

The validator is the one soft gate, because it is a binary this machine and
all four CI legs lack, and requiring it would make the verb unusable
everywhere. Absent is loud and reaches the record as a sentence. That is not
a stored verdict of the kind the ledger refuses: policy moves under a fixed
record and is recomputed, while whether these bytes were checked is a fact
about bytes that do not change.

## An installed klin could not start, and had not been able to for six sessions

Found by a packaging assertion written for the new script and immediately
true of everything else. `packages = ["klin"]` built a wheel holding the nine
top-level modules and none of `fetch/`, `gen/` or `index/`, so `from . import
fetch` on cli's first line raised ImportError before the parser existed. Every
install route in the README produced that package. Nine files where there
should be twenty.

76ede35 found this in session 6 and fixed it. e9d493d reverted the fix on a
measurement that built both ways and found the wheels identical and complete.
That measurement was real and its conclusion was wrong, and the mechanism is
worth recording because it will fool the next person the same way: bdist_wheel
zips `build/lib` wholesale and nothing cleans it between builds, so an earlier
build under the explicit list had already left the subpackages there and both
later builds found them waiting. Reproduced deliberately here. With a stale
`build/` the explicit list still yields a wheel carrying all eleven subpackage
files; with `build/` removed it yields none.

The suite could never have caught it, because the suite imports the source
tree and the archive is precisely what it does not look at. A second CI job
now builds from a clean checkout, asserts the files that must be present,
installs the wheel and runs `klin --help` from a directory that is not the
repository. That last step is the one that matters: importing from a checkout
is what hid this for six sessions.

## Three defects the first real Blender run found

All three are about what an exporter writes, which is what a stub cannot
reach, and all three would have shipped.

**The atlas was embedded rather than referenced.** Blender wrote the image
both ways at once, a one-pixel placeholder in a buffer view and a uri beside
it, which the specification forbids, with the uri relative to the temporary
directory the export ran in and therefore pointing nowhere once the file
moved. Either half alone defeats the verb: a private copy stops moving when
the project re-grades the shared atlas, and a prop stranded on the old palette
reads as a shading bug three steps from its cause. klin now rewrites the image
after the export and before the gates. Doing that rather than hunting a better
exporter keyword is deliberate, because the invariant is klin's and an
exporter argument that means one thing this release and another next is not
something to hang it on.

**A second uv layer shipped intact.** A mesh can carry several and only one is
active, so pinning the active one left the other exporting the coordinates the
mesh arrived with, as TEXCOORD_1. The verify pass read only the active layer
too, so the gate meant to catch exactly this was blind to it. Extra layers are
now dropped before anything is written, and the verify reads every layer.

**Point filtering and the v flip were right first time**, which is worth
recording because they were the two most likely to be wrong. The exported
sampler is 9728 and the measured uvs sit on the table's texels to four decimal
places, so the flip is correct in both directions rather than accidentally
symmetric.

## TRELLIS.2 arrives, with the patch that makes it legitimate

Two scripts move here from the consuming project, where they had been living
as a recorded and deliberate boundary violation: they were licence evidence
for that project's decision log, and klin had no `gen` verb to hold them when
they were written.

The adapter carries generation and the install patch together, because
splitting them would leave a generator whose licence status depended on a step
somebody remembered to run. The proof is a removal rather than a reading,
since a transitive import three modules deep does not appear in a diff: the
harness takes nvdiffrast, nvdiffrec and nvdiffrec_render out of the import
system for the whole process and generates anyway.

One thing is new against the scripts it adopts. Whether an edit is present is
detected by a fingerprint that does not name the tool that wrote it, so an
install already patched under the previous name reads as patched rather than
being patched again on top of itself. Reverting is the other way round and
will only undo text klin recognises as its own. Confirmed against the real
install, whose three copies were patched by the older script and which klin
reads as patched without touching.

`gen.posture` now takes `(name, role)` pairs rather than a node graph. Only
one generator describes its work as a graph, and asking the rest to invent one
to reach the licence check would be the tail wagging the dog.

## Decisions worth remembering

- **A test suite that imports the source tree says nothing about the archive.**
  Six sessions of green CI over a package that could not start. Anything about
  packaging has to be asserted against a built artifact and an install.
- **A measurement can be real and its conclusion wrong.** The revert that
  re-broke the wheel was not careless; it was defeated by a stale build
  directory. Clean the tree before comparing two builds.
- **Read back the file that shipped, not the object in memory.** Both the uv
  convention and the embedded atlas were invisible from inside Blender and
  obvious in the exported bytes.
- **Detect a patch by a fingerprint, not by the name of who wrote it**, or
  renaming the tool silently converts every patched install into one that
  looks unpatched and gets patched twice.
- **Refuse an import rather than stubbing it** when the claim is that
  something never ran. A stub leaves open what the code did with it; a refusal
  makes any use a loud traceback whose absence is the evidence.

## What is next

- **The validator is wired and unproven.** Its command line and json shape are
  isolated in one function so confirming them against a real install is a
  change to that function alone. Until then the gate is soft by design.
- **`--strict` should probably become the default** once a validator is on the
  machines that matter, and the record's not-validated sentence is what makes
  that transition visible.
- **A `gltf` conformer with no Blender.** The common case is a mesh already
  carrying one material per swatch, which is a uv accessor rewrite in stdlib
  `struct` and `json`. The registry exists for a second member and this is the
  obvious one.
- **Batching.** Blender costs two to four seconds of process start per file,
  irrelevant for one prop and a minute for twenty. The job file already
  accommodates a list; nothing was built.
- **Licence drift on a derivative.** A conformed record copies its source's
  licence at the moment it is made, so amending the source later leaves the
  copy stale. `source.derived_from` is the field a rule that noticed would key
  on, and no rule kind can express it yet. Named in the module docstring
  rather than assumed covered.
