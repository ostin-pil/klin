# Session 4 — The fetch adapters

**Date:** 2026-08-24
**Branch:** `feature/session-4-fetch` (worktree `.claude/worktrees/session-4-fetch`)

Session 3 built the credential layer for adapters that did not exist yet. This
session built them: `klin fetch hf` and `klin fetch civitai`, the download
guards underneath, and the licence mapping that is the actual point of the
exercise.

## What the registry is for

`cli.py` has carried a promise since session 1, in its own docstring: vendors
arrive as adapters and "adding one must never require touching this file's
structure." A list of imports in `cli.py` would have broken that on the first
addition, so `klin/fetch/` discovers instead. Any module declaring `NAME` and
`configure` becomes a subcommand. `cli.py` gained one verb and delegates.

There is a test that writes a module into the package at runtime and asserts it
becomes a working subcommand with argument parsing. The promise is checked
rather than trusted, which is the only way a promise in a docstring survives
contact with a third vendor.

## The mapping, which is the substance

HuggingFace publishes an identifier, so the adapter records it and lets
`policy.families` classify it. It decides nothing itself. `license:other` maps
to nothing, is reported as `unknown`, and prints an instruction to settle it
with `--families`.

That last part is the rule the module exists to hold. `license:other` covers
Flux.1-dev and the Shakker ControlNet, the two largest things Barinn fetches,
and both are in fact noncommercial. An adapter that quietly decided
`noncommercial` for `license:other` would therefore look correct on the two
repositories anybody checked, and be wrong invisibly on every later one. A
refusal appears in the audit; an invention does not.

Civitai publishes no identifier at all, only permission flags, so the mapping is
a judgment. It lives in the module docstring, in the record's `notes`, and in
the README, and the raw flags go into the record beside the derived families so
a reader who disagrees can see the input. The whole API response is kept in a
`meta.json` sidecar, which is what makes a later re-classification possible
without a second download.

The contested row: `Rent` and `RentCivit` grant a generation service permission
to run a model. They do not answer whether an image made with it may be sold,
which is the question Barinn's rule 4 actually asks, so a model offering only
those is treated as noncommercial. Records carry a `LicenseRef-` id, SPDX's own
convention for terms that are not on its list.

## The mapping was validated before it was written

The table was run against the live Civitai API for the eight models Barinn
intends to acquire, and the results are the test fixtures. Two of the eight
contradicted the plan that specified them:

- **Diorama (60962) is not clean.** It sets `allowNoCredit: false`, so it
  carries `attribution`. It still passes a ship gate, since rule 4's deny list
  does not include that family, but it carries a permanent per-asset credits
  obligation and it arms rule 3 against Steam's DRM wrapper. K. ruled the same
  day that this is acceptable because the asset is evaluation-only. The record
  still carries the family, because the audit's value is accuracy rather than
  convenience.
- **FLUX64 (660136) and 3DMM_FLUX (650444) carry `noderivatives` too.** Both
  set `allowDerivatives: false`. The verdict does not change, since both
  families sit in rule 4's deny list, but the records now say so.

## Three things the build turned up

**A denylist of one value is not a guard.** The plan specified guard 1 as
"Content-Type is not `text/html`". The real refusal, observed while verifying
the credential, is Cloudflare answering `403 error code: 1010` with
`Content-Type: text/plain` and a seventeen-byte body. A denylist of `text/html`
waves that through to be written as a `.safetensors`. Guard 1 is now an
allowlist of binary content types. Guards 2 and 3 would have caught it a moment
later, but guard 1 exists to fail early with a message naming the cause, and
against a denylist of one it would not have.

**Every request needs a browser User-Agent.** The same block is what
`Python-urllib/3.x` earns from Civitai's edge on every request. Without one,
nothing downloads regardless of the credential, and the failure reads like a
rejected token. `net.py` sends a real agent and reports `1010` as the client
being refused rather than the credential.

**`files_metadata=true` is the wrong HuggingFace parameter.** It looks like the
one that returns file sizes and instead returns siblings with every size set to
`null`. A guard built on it does not error; it silently degrades to checking
nothing, which is the worst way for a guard to fail. `blobs=true` is the
parameter that works, and it returns the 17,246,524,772 bytes an independent
`HEAD` had already measured.

## The cache_dir defect

`manifest.resolve()` does `os.path.join(repo, value)`, which is right for
`ledger` and `staging_dir` and wrong for `cache_dir`. Barinn's manifest sets it
to `%LOCALAPPDATA%/klin/cache`, and joined to a repo root that becomes a literal
`%LOCALAPPDATA%` directory inside the tree. Wrong in both halves, and wrong
quietly, because that is a legal directory name on Windows and a download would
have succeeded into it.

`manifest.cache_dir()` is its own resolver: expandvars, expanduser, no join, and
an error rather than a guess when a variable is unset or the result is relative.
`KLIN_CACHE` overrides the manifest, which keeps "this machine's weights go on
D:" out of a file committed to Barinn.

## Cache reuse, and why it is a session boundary

`--as <subdirectory>` hardlinks a cached file into a models tree rather than
copying it, because a checkpoint is seventeen gigabytes, and rather than writing
a search-path config because a tree may already be reached through a junction,
in which case a config registers one directory under two names. That is not
hypothetical: `D:\ComfyUI\models` is a junction to `D:\comfy-models`.

`verify_existing` then makes a second run cheap. It is not a memory of having
succeeded: the declared size must still match, the format must still parse, and
the digest is recomputed rather than recalled, because a recalled digest proves
the download worked once and says nothing about the file that is there now.

This is what lets acquisition and recording live in different sessions. Barinn's
ledger belongs to a Barinn branch, so this session downloads into the cache and
Barinn's own session re-runs the same commands to write its records, which now
costs under a second per file rather than a re-download.

## Verified by hand, not only by tests

The 139 tests use no network. These did:

- `klin fetch civitai 1041229 --dry-run` refuses to guess among five versions
  and lists them, which is the behaviour that stops a Flux LoRA being fetched
  when the workflow wanted the Z-Image one.
- A real fetch of `dark_fantasy_illustration_Flux-000031.safetensors`:
  19,299,760 bytes, sha256 matching the hash Civitai publishes, and
  independently confirmed with `certutil -hashfile`.
- `fsutil hardlink list` confirms the cached file and the models-tree file are
  one file with two names, not a copy.
- A second run of the same command printed "already cached and verified" and
  finished in 0.5 seconds.
- End to end against Barinn's real manifest in a scratch repo: the stage gate
  passes both records, and the ship gate fails FLUX64 on rule 4, quoting
  Barinn's policy text verbatim.

## Still open

- `klin gen` is untouched. Driving ComfyUI and stamping `produced_by` onto
  rendered output is the other half of the adapter surface and a larger build.
- The KeePassXC resolver handed over by session 3 is still unbuilt, so the
  Civitai credential is stored in the OS vault by hand rather than resolved from
  the database on demand. That blocks nothing here.
- `policy.py` does not know `openrail`. The plan for this session asserted that
  `openrail++` maps directly; it does not, and the permissive table is
  MIT/Apache/BSD/ISC/Zlib only. An openrail licence therefore falls to `unknown`
  and the hand-classification path, which is the safe behaviour. Teaching klin a
  new family is a policy change and belongs to a session that decides it
  deliberately.
