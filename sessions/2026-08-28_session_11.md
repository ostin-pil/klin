# Session 11: the gate that could not survive meeting its own validator

**Date**: 2026-08-28
**Branch**: `feature/session-11-validator` (worktree, `.claude/worktrees/session-11-validator`)

## Why now

The consuming project installed the Khronos `gltf_validator` — the binary the
fourth gate had been wired for since session 8 — and pointed conform at the
first real bought mesh it ever had. The run died before reporting a single
finding. Installing the validator made conform strictly worse than not having
one, which is the opposite of what a gate is for, and it blocked the intake
the install was supposed to unblock.

## The two defects

**The command line.** `gltf_validator <file>` prints a human summary to
stdout and writes its json to `<file>.report.json`; json on stdout takes
`-o`. `validate()` ran without the flag, tried to parse the prose, and raised
— taking the whole conform down before the slot and triangle gates could
report. The function's own docstring had said confirming the real command
line "should be a change to this function and to nothing else", and it was:
one flag. The stubbed tests could not have caught it because session 8's
stub replaced `validate()` wholesale; the command line is now pinned by a
test one level lower, against a fake `subprocess.run`.

**The location.** With `-o` fixed, the validator reported exactly one error:
`IO_ERROR: Resource not found (../atlas.png)`. That error is klin's own
manufacture — the atlas uri is written relative to where the file lands
after the gates pass, deliberately (session 8), and the gates run while the
file still sits in the working directory, where the uri resolves to nothing.
Neither validating the pre-relink file (that judges Blender's output, not
what ships) nor filtering the error (teaching the gate to ignore the exact
class of thing it exists to catch) is honest. `validation_stage()` copies
the produced bytes into a directory nested deep enough that the uri's
parent-hops stay contained, puts the atlas bytes at the spot the uri names,
and hands the validator that copy: the same bytes, with the context they
will really have. The copy stays behind with the rest of the working
directory, so a failure message pointing at it stays inspectable.

## Proven

378 tests (375 + 3). Live against the consuming project's first bought
mesh: the run now reaches the findings and reports the honest failures — a
slot named `Bar` wanting `--map`, and 26,672 triangles against a budget of
900 — with the validator running clean beside them instead of ahead of them.
